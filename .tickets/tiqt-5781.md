# Stop using dict.get with silent defaults for missing keys

## Description

Style rules forbid dict.get(key, default) as a fallback for missing data. Sites: store.py:399 'graph.get(source, [])' and store.py:411 'graph.get(node, [])' in the dep graph -- a missing node here means an unknown ticket ID, which should be an error not an empty neighbour list. query.py:216-217 'dep = all_tickets.get(dep_id); if dep and dep.status not in TERMINAL' silently treats a dangling dep as non-blocking, so 'tq ls --ready' shows a ticket as actionable while 'tq validate' flags the same dep as broken. Fix: assert membership where the key must exist; for the dangling-dep case, treat unresolved dep IDs as blocking (or surface them) so --ready and validate agree.
