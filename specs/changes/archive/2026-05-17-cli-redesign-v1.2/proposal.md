# Proposal: CLI redesign v1.2

## Why

The current `tq` CLI exposes fifteen per-field mutation verbs (`tag`, `untag`,
`dep`, `undep`, `nest`, `unnest`, `link`, `unlink`, `assign`, `change-prio`,
`change-type`, `describe`, `add-note`, `xref`). Every new field-level change
needs its own verb, the help screen is long, and there is no way to make
several changes to a ticket in one invocation. The status vocabulary also
carries a long-standing wart: the terminal value is `completed` (verb-tense)
while the inverse is `canceled` (adjective-tense), and the user-facing verb
is `close`.

v1.2 unifies all post-creation mutation under one `edit` command sharing a
single field-flag vocabulary with `create`, and renames the terminal status
`completed` → `closed` so the vocabulary matches the verb.

## What Changes

- **BREAKING**: removes the per-field mutation verbs `tag`, `untag`, `dep`,
  `undep`, `nest`, `unnest`, `link`, `unlink`, `assign`, `change-prio`,
  `change-type`, `describe`, `add-note`, `xref`. No aliases.
- **BREAKING**: introduces a single `edit <id> [field-options]` command that
  accepts every `create` field-option plus removers (`--untag`, `--undep`,
  `--unlink`, `--unset {parent,xref,assignee}`) and a `--title` renamer.
- **BREAKING**: renames terminal status `completed` → `closed`. The
  user-visible verb (`close`) and the stored status now match.
- **BREAKING**: `create` title becomes a required positional. The optional
  form is removed.
- Adds `--link` and `--note` field-options to `create` (already valid on
  `edit`), so new tickets can be linked and annotated in one call.
- Removes the `-T` short for `ls --tag`; `--tag` is short enough.
- `autofix` unconditionally rewrites legacy `status: completed` →
  `status: closed` to migrate existing tickets.

## Capabilities

### New Capabilities

- `ticket-edit`: the consolidated `edit` command. Owns every field-flag,
  the set/unset conflict rule, repeatability semantics, and the `--unset`
  enum.

### Modified Capabilities

- `ticket-lifecycle`: `create` title required; gains `--link` and `--note`.
  Terminal status renamed `completed` → `closed`.
- `ticket-relationships`: standalone mutation commands (`dep`, `undep`,
  `nest`, `unnest`, `link`, `unlink`) removed; capability slims to
  cycle-detection (invoked from `edit --dep`) and the read-only `deps` /
  `links` listings.
- `ticket-query`: `--status` enum `completed` → `closed`; `ls --tag` loses
  the `-T` short.
- `ticket-validate`: terminal-state vocabulary aligns on `closed`.
- `ticket-autofix`: new requirement to rewrite legacy
  `status: completed` → `status: closed`.
- `ticket-store`: terminal-state constant renamed.

### Removed Capabilities

- `ticket-fields`: folded into `ticket-edit`.
- `ticket-content`: folded into `ticket-edit`.

## Impact

- **Code**: deletes `commands/fields.py`, `commands/content.py`, and the
  mutation handlers in `commands/relationships.py`; adds `commands/edit.py`;
  modifies `cli.py`, `commands/lifecycle.py`, `commands/query.py`,
  `commands/autofix.py`, `commands/validate.py`, `store.py`.
- **Tests**: deletes `test_cli_fields.py` and `test_cli_content.py`; rewrites
  `test_cli_relationships.py` to retain only read-only and cycle-detection
  cases; adds `test_cli_edit.py`; updates `test_cli_help.py`,
  `test_cli_lifecycle.py`, `test_cli_query.py`, `test_cli_validate.py`,
  `test_cli_autofix.py`, `test_store.py`, and `conftest.py` for vocabulary
  and signature changes.
- **Test drives**: rewrites `05-field-mutations.md`; touches
  `01-basic-lifecycle.md` and `10-scoping-by-parent-and-dep.md`.
- **Docs**: promotes `cli-design-v1.2.md` to `cli-design.md`; appends a
  v1.1→v1.2 section in `migration-notes.md`; refreshes `README.md`,
  `architecture.md`, `CHANGELOG.md`.
- **Skill + plugin**: `.shablon/templates/skills/tiquette/SKILL.md` and the
  prime hook are regenerated by shablon from the new `tq --help`; the
  hand-written sections of the SKILL template need updating.
- **Release**: bumps `project.version` (still 0.x) and ships an
  `autofix`-based one-shot migration for existing repos.

The implementation map in `docs/v1.2-implementation-map.md` is the
exhaustive inventory.

## Constraints

- Backward compatibility is explicitly not preserved at the CLI surface.
  Removed verbs are gone, not aliased. The migration is a one-time
  `autofix` for on-disk data.
- The `.tickets/` on-disk format stays compatible; only the `status`
  field's vocabulary changes.

## Out of Scope

- Any change to `deps`, `links`, or `tags` read-only listing commands.
- Any change to `id-resolution`.
- Any change to the ticket file format beyond the `status` rename.
- Interactive `edit` mode (e.g., dropping into `$EDITOR`). Not in v1.2.
