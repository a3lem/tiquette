# v1.2 implementation map

Exhaustive list of code, tests, docs, specs, and assets touched by the v1.2
CLI redesign (see `cli-design-v1.2.md`). Used as input to the spec change.

## 1. Source code

### Entry point
- `src/tiquette/cli.py` — replace `HELP_SUMMARY` + `HELP_TEXT`; drop `register()`
  calls for removed verb groups; add `edit` registration.

### Command modules to DELETE
The behavior folds into `edit`:
- `src/tiquette/commands/fields.py` (assign, change-prio, change-type, tag,
  untag, xref)
- `src/tiquette/commands/content.py` (describe, add-note)
- Mutation handlers in `src/tiquette/commands/relationships.py` (dep, undep,
  nest, unnest, link, unlink). The `deps`/`links` listing commands stay (they
  already live in `query.py`).

### Command modules to MODIFY
- `src/tiquette/commands/lifecycle.py` — `create` gains `--link` and `--note`
  (repeatable). `--link` writes both sides (symmetric, same atomic-write
  pattern as the former standalone `link` command). `--note` uses the
  creation timestamp for the note's `at` field. Title becomes required
  (`[title]` → `<title>`). Field-flag set shared with `edit`.
- `src/tiquette/commands/query.py` — `ls -s` enum: `completed` → `closed`;
  `archive` wording; remove `-T` short on `--tag`.
- `src/tiquette/commands/autofix.py` — add unconditional migration:
  existing `status: completed` → `status: closed`.
- `src/tiquette/commands/validate.py` — terminal-state checks reference
  `closed` not `completed`.

### Command module to CREATE
- `src/tiquette/commands/edit.py` — owns the `edit` subcommand. Shares
  create's field-flag builder; adds `--title`, `--untag`, `--undep`,
  `--unlink`, `--unset FIELD` (FIELD ∈ {parent, xref, assignee});
  enforces set/unset conflict; appends notes; replaces description.

### Store layer
- `src/tiquette/store.py` — audit terminal-state constants
  (`completed` → `closed`). Helpers used by removed handlers (`add_tag`,
  `set_parent`, `add_dep`, `add_link`, `set_assignee`, `set_xref`,
  `set_description`, `append_note`, …) stay and are re-wired through `edit`.

## 7. Resolved decisions

1. **Capability layout**: create new `ticket-edit` REFERENCE capability.
   REMOVE `ticket-fields` and `ticket-content`. Slim
   `ticket-relationships` to cycle-detection + listings only.
2. **`create` title**: always required (positional `<title>`).
3. **`--note` on `create`**: included. Note timestamp is the moment of
   the `create` call (same clock used for the ticket's `created` field).
4. **`--link` on `create`**: symmetric, same atomic-write pattern as the
   former standalone `link`. Both sides of the link are written.
5. **`--unset` targets**: `{parent, xref, assignee}` only. `description`
   is dropped from the target set — semantics for unsetting a body are
   ambiguous and the operation is unlikely to be needed.
   **Action**: update `cli-design-v1.2.md` to drop `description` from
   the `--unset` enum.
6. **`autofix` migration**: runs unconditionally. `status: completed`
   is always rewritten to `status: closed`.
7. **`-T` removal**: confirmed.
8. **`deps` / `links` / `tags` listing commands**: confirmed standalone
   (read-only, no fold-in).
